# 12. Detailed Design

## 1. 타입 (`src/lib/types.ts`)

```ts
type Category = 'dev' | 'daily';
type Difficulty = 1 | 2 | 3;
type Question = { id; category; difficulty; prompt; choices: string[]; answer: number; explanation };
type TodayResult = { date; correct; total; xpGained };
type Attempt = { date: string; ids: number[]; picks: number[] };
type Progress = { xp; streak; lastDate: string | null; today: TodayResult | null; attempt: Attempt | null; seen: number[] };
```

## 2. 날짜

### `dateKey(d)`
- `getFullYear()`, `getMonth()`, `getDate()`로 로컬 날짜를 `yyyy-mm-dd`로 만든다.

### `todayKey(dateKey)` (`storage.ts`)
- 토스 앱 안이고 `Environment.getServerTime.isSupported()`이면 서버 시간(ms)으로 `Date`를 만들어 `dateKey`에 넘긴다.
- 그 밖에는 기기 시계를 쓴다. 기기 시간을 바꿔 문제를 넘기는 조작은 토스 앱 안에서는 막힌다.

### `dayNumber(key)` (내부)
- `Date.UTC(y, m - 1, d) / 86_400_000` 내림. 연속된 날짜는 정확히 1 차이가 난다.

## 3. 문제 선택 (`daily.ts`)

### `difficultyMix(level)`
레벨별 5문제의 난이도 배열. [04_기능_명세서](04_기능_명세서.md) F-09 표와 같다.

### `rank(id, key)` (내부)
`"{key}#{id}"` 문자열의 FNV-1a 해시. 같은 날짜면 같은 순서, 날짜가 바뀌면 다른 순서가 나온다.

### `pickDaily(questions, key, level = 1, seen = [], salt = '', categories = ['dev', 'daily'], count = 5, records)`
```
pool = categories에 속한 문제 (하나도 없으면 전체)
ordered = 안 본 문제 먼저. 안 본 문제끼리는 rank 오름차순,
          본 문제끼리는 복습 순서(틀린 문제·오래전에 본 문제 먼저, records)
order = 일번호가 짝수면 categories, 홀수면 거꾸로
for slot, difficulty in difficultyMix(level, count):
    category = order[slot % order.length]
    unseen = 아직 안 고른 문제 중 안 본 문제
    best = (unseen 중 난이도 일치 & 분류 일치)
        ?? (unseen 중 난이도 일치)
        ?? (unseen 중 난이도 차이가 가장 작은 것, 같으면 분류 일치 먼저)
        ?? (본 문제 중 난이도 차이가 가장 작은 것)   ← 새 문제가 모두 떨어졌을 때만 복습
    picked에 추가
```
- 결과 개수는 `min(count, 문제 수)`. `categories`는 맞춤 설정의 `profileCategories()`, `count`는 하루 목표다.
- 2026-10-25 전에는 원하는 난이도의 새 문제가 떨어지면 같은 난이도의 본 문제를 먼저 냈다. 지금은 가까운 난이도의 새 문제가 먼저다 ([20_문제_은행_확장](20_문제_은행_확장.md)).

### `startAttempt(progress, questions, key)`
```
if attempt.date == key and 고정 문제가 모두 은행에 있음 → progress 그대로
ids = pickDaily(questions, key, levelFromXp(xp), seen)
if ids 비어 있음 → progress 그대로 (무한 갱신 방지)
return { ...progress, attempt: { date: key, ids, picks: [] }, seen: seen ∪ ids }
```

### `recordPick(progress, index, choice)`
- `index`가 `picks.length`와 같을 때만 추가한다. 이미 답한 문제(`index < picks.length`)나 건너뛴 문제는 무시한다.

### `countCorrect(questions, picks)`
- `picks[i] === questions[i].answer`인 개수.

### `completeDay(progress, key, correct, total)`
```
if today.date == key → progress 그대로
consecutive = lastDate가 key의 하루 전
return { ...progress, xp + correct×10 + 5, streak: consecutive ? streak+1 : 1, lastDate: key, today }
```
- `attempt`, `seen`은 그대로 둔다.

### `visibleStreak(progress, key)`
- `lastDate`가 오늘이나 어제면 `streak`, 아니면 0.

## 4. 레벨 (`level.ts`)

- `xpToReach(L) = 60 × L × (L − 1) / 2`
- `levelFromXp(xp)`: L = 1부터 `xp ≥ xpToReach(L + 1)`인 동안 올린다.
- `levelProgress(xp)`: `current = xp − xpToReach(L)`, `needed = 60 × L`.

## 5. 저장 (`storage.ts`)

| 함수 | 동작 |
|------|------|
| `isInToss()` | `window.ReactNativeWebView`가 있으면 true |
| `parseProgress(raw)` | JSON 파싱, 필드별 타입 검사, `today`·`attempt`는 형태까지 검사 |
| `loadProgress()` | 토스 앱 안: SDK `Storage.getItem` → 값 없거나 실패 시 localStorage |
| `saveProgress(p)` | localStorage에 쓰고, 토스 앱 안이면 SDK `Storage.setItem`에도 쓴다 |

SDK는 `await import('@apps-in-toss/web-framework')`로 토스 앱 안에서만 불러온다.

## 6. 컴포넌트 (`DailyChallenge.tsx`)

### `DailyChallenge`

| 상태 | 초기값 | 설명 |
|------|--------|------|
| `progress` | `null` | 불러오기 전 null |
| `today` | `''` | 오늘 날짜 키 |

| 효과 | 동작 |
|------|------|
| 마운트 | `loadProgress()`, `todayKey()`. `visibilitychange`로 화면에 돌아올 때 날짜 재확인 |
| `progress`·`today` 변경 | 오늘 미완료면 `startAttempt()`. 바뀌었으면 저장 |

- `update(next)`: 상태를 바꾸고 바로 저장한다.
- 렌더링: 완료면 결과, `attempt`가 오늘 것이면 `Quiz`(key = 날짜), 그 외에는 아무것도 그리지 않는다.

### `Quiz` (제어 컴포넌트)

| props | 설명 |
|-------|------|
| `questions` | 오늘 고정 문제 |
| `picks` | 저장된 답 |
| `onPick(index, choice)` | 부모가 `recordPick` 후 저장 |
| `onFinish()` | 부모가 `countCorrect` → `completeDay` 후 저장 |

- 내부 상태는 현재 문제 번호 `index`뿐이다. 초기값은 `min(picks.length, 문제 수 − 1)`이라 이어 풀기가 된다.
- 답 여부는 `picks[index]`로 판단한다.

## 7. 해결한 한계 (2026-10-21)

| # | 한계 | 해결 |
|---|------|------|
| 1 | 풀이 중 앱을 닫으면 처음부터 다시 풀어 XP를 더 받을 수 있음 | 답을 고를 때마다 저장, 이어 풀기 |
| 2 | 자정을 넘겨 열어 두면 전날 문제로 완료 처리 | `visibilitychange` 때 날짜 재확인 |
| 3 | 문제 추가 시 날짜별 문제가 바뀜 | 하루 시작 때 문제 ID 고정 |
| 4 | `today` 필드 형태 미검증 | `parseToday`, `parseAttempt` 추가 |
| 5 | 기기 시간 조작 | 토스 앱 안에서는 서버 시간 사용 |

## 8. 남은 한계

| # | 한계 | 영향 | 개선안 |
|---|------|------|--------|
| 1 | 화면을 계속 띄워 둔 채 자정을 넘기면 다음 visibilitychange 전까지 전날 문제 | 작음 | 타이머로 자정 감지 |
