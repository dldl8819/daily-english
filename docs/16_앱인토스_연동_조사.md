# 16. 앱인토스 연동 조사

- 조사일: 2026-10-21
- 방법: 앱인토스 개발자센터 문서와 커뮤니티 글 확인, SDK 3.8.1 패키지 타입 정의(`index.d.ts`, `config.d.ts`)와 CLI 직접 확인

## 1. 배포 방식

| 항목 | 확인 내용 | 근거 |
|------|-----------|------|
| SDK | `@apps-in-toss/web-framework` (최신 3.8.1) | npm |
| 설정 파일 | `apps-in-toss.config.ts`, `defineConfig` (3.x). 2.x는 `granite.config.ts`였고 `ait migrate`로 변환 | 공식 튜토리얼, CLI 도움말 |
| 설정 필드 | `appName`, `brand.primaryColor`, `permissions`, `navigationBar`, `webView`, `webBundleDir` | `config.d.ts` |
| appName | 콘솔에 등록한 이름과 같아야 업로드 가능. 딥링크 `intoss://{appName}`, 콘솔 QR 테스트는 `intoss-private://{appName}` | 공식 튜토리얼 |
| 빌드 | `ait build`가 `webBundleDir`을 그대로 `.ait` 파일로 묶음. 웹 빌드를 먼저 해야 함 | CLI 소스 |
| 업로드 | 콘솔에 `.ait` 업로드 또는 `ait deploy` (API 키, 워크스페이스) | CLI 도움말, 공식 튜토리얼 |
| 출시 전 | 토스 앱 테스트를 마쳐야 출시 요청 가능 | 공식 튜토리얼 |
| Next.js | 수동 패키징(`createArtifact` 직접 호출)은 지원 안 함. `ait build`로 해결된 사례 있음 | 커뮤니티 |

**프로젝트 반영**: `apps-in-toss.config.ts` 추가, `webBundleDir: 'out'`, `npm run build:ait`로 `daily-english.ait` 생성 확인.

### 시작 방식

- 공식 시작 방법은 `npx create-ait-app <app-name>`(React + Vite 템플릿)이다. 이 프로젝트는 그 방법을 쓰지 않고 Next.js 프로젝트를 만든 뒤 SDK를 설치하고 `apps-in-toss.config.ts`를 직접 작성했다.
- 그대로 두어도 되는 근거: WebView 튜토리얼은 기존 웹 프로젝트에 SDK를 설치하는 방법을 안내하고, 앱인토스 에이전트 플러그인(`toss/apps-in-toss-harness`)의 devtools 주입도 Vite·Next.js·Rspack·Webpack을 지원한다. `ait build`로 `.ait` 생성도 확인했다.
- 공식 템플릿에 기본으로 들어 있는 devtools(브라우저에서 SDK API 흉내)는 아직 없다. 플러그인의 `/ait:inject-devtools`로 넣을 수 있다.

### 릴리즈 노트 중 이 프로젝트와 관련된 것

| 버전 | 내용 | 영향 |
|------|------|------|
| 3.0.4 | `pullToRefreshEnabled` 기본값 false | 영향 없음 (쓰지 않음) |
| 3.1.1 | WebView origin 변경 (`{appName}.apps.tossmini.com`) | localStorage가 이어지지 않을 수 있음. SDK `Storage`를 쓴 이유 |
| 3.5.0 | `NavigationBar.setOptions` 추가 | 화면 모드에 사용. 3.8.1이라 사용 가능 |
| 3.6.0 | `User.createAnonymousKeyAuthCode` 추가 | 서버 연동(F-10) 때 사용자 확인에 사용 |

출처: [릴리즈 노트](https://developers-apps-in-toss.toss.im/release-note)

## 2. 사용한 SDK API

| API | 용도 | 비고 |
|-----|------|------|
| `Storage.getItem` / `setItem` | 진행 상황 저장. "앱이 종료되어도 유지" | 토스 앱 안에서만 동작 |
| `Environment.getServerTime` | 기기 시계 대신 서버 시간으로 날짜 결정 | 토스 5.245.0 이상, `isSupported()`로 확인 |
| `window.ReactNativeWebView` | 토스 WebView 여부 판별 | SDK 내부 판별 방식과 동일 |
| `NavigationBar.setOptions({ theme, backgroundColor })` | 화면 모드에 맞춰 내비게이션 바 색 변경 | 토스 앱 안에서만 동작 |
| `User.getAnonymousKey()` | 사용자 식별키(`hash`)를 받아 진행 상황에 저장. 저장된 키와 다르면 다른 사용자로 보고 새로 시작 | 토스 5.232.0 이상, 실패하면 키 없이 동작 |

**사용자 식별키**: 비게임 체크리스트의 "사용자 식별값을 확인·저장하고 미니앱이 정상 시작된다" 항목은 로그인 여부와 상관없는 공통 항목이다. 처음에 "로그인이 없어 해당 없음"으로 판단했다가 바로잡았다. 같은 미니앱 안에서는 앱 삭제·기기 변경 후에도 같은 키다. ([사용자 식별키 가이드](https://developers-apps-in-toss.toss.im/guide/authentication/anon-key))

### SDK 버전과 광고 (2026-10-21 업데이트 확인)

- 2026-10-26부터 인앱 광고의 배너 광고에 토스 네이티브 광고가 추가되고, **WebView SDK 3.0.5 이상에서만** 지원된다. SDK 2.x와 React Native는 지원하지 않는다.
- 이 프로젝트는 3.8.1이라 조건을 충족한다. 현재 광고는 없으며, 나중에 배너 광고를 붙이면 3.x의 `TossAds` API를 쓴다.
- 출처: [10월 21일 앱인토스 업데이트](https://toss.im/apps-in-toss/blog/update-26-10-21)

SDK에 `Migration.getOriginStorage()`가 있다. WebView origin이 바뀌면 localStorage가 이전되지 않을 수 있다는 뜻으로 보고, 토스 앱 안에서는 SDK `Storage`를 쓰기로 했다.

## 3. 비게임 출시 가이드 중 이 앱에 해당하는 항목

| 항목 | 이 앱의 대응 | 상태 |
|------|--------------|------|
| 서버 렌더링 금지, CSR·SSG만 | `output: 'export'` 정적 생성 | 대응 |
| 테마는 라이트 모드 | 기본은 라이트, 기기 다크 모드를 따르지 않음. 접근성을 위해 사용자가 직접 고르는 "어둡게" 모드는 둠 ([17_접근성](17_접근성.md) 3장) | 대응, 허용 여부 문의 필요 |
| 핀치 줌 비활성화 | viewport `maximumScale: 1`, `userScalable: false` | 대응 |
| 앱을 껐다 켜도 데이터 유지 | SDK `Storage` 사용 | 대응, 실기기 확인 필요 |
| 앱인토스 내비게이션 바 사용 | 설정 파일 `navigationBar` | 실기기 확인 필요 |
| 첫 화면에서 뒤로가기 시 종료 | 단일 페이지라 기본 동작에 맡김 | 실기기 확인 필요 |
| 자체 로그인 금지 (토스 로그인만) | 로그인 없음 | 해당 없음 |
| 사용자 식별값 확인·저장 | `User.getAnonymousKey` → `progress.userKey` | 대응, 실기기 확인 필요 |
| 진입 시 바텀시트 자동 노출 금지 | 바텀시트 없음 | 해당 없음 |
| `eval` 등 외부 코드 실행 금지 | 사용 안 함 | 대응 |
| 화면 전환·터치 지연 2초 이상 금지 | 번들 115 kB, 네트워크 요청 없음 | 실기기 확인 필요 |
| 비속어·과도한 유행어 금지 | 문제 검수 시 확인 | 검수 중 |

### 앱인토스 에이전트 플러그인 점검 (`launch-scan.sh`)

- 결과: `dark-theme=2`. 사용자가 고르는 "어둡게" 모드 CSS와 그 테스트를 잡은 것으로, 의도한 것이다 ([17_접근성](17_접근성.md) 3장).
- `viewport-zoom`은 HTML 파일이 없어 건너뜀(Next.js가 빌드 때 viewport를 만든다. `out/index.html`에 `user-scalable=no` 확인).

## 4. 아직 확인하지 못한 것

| 항목 | 이유 | 확인 방법 |
|------|------|-----------|
| 토스 앱 실기기 동작 (저장, 내비게이션 바, 뒤로가기) | 콘솔 등록·QR 테스트 필요 | 콘솔에 `.ait` 업로드 후 QR |
| Next.js 정적 파일 경로(`/_next/...` 절대 경로)가 WebView에서 열리는지 | 실기기 필요 | 위와 같음 |
| 앱 아이콘·이름 설정 위치 | 3.x 설정 타입에 아이콘 필드가 없음. 콘솔 앱 정보로 관리하는 것으로 보임 | 콘솔 확인 |
| 사업자 등록 필요 여부 | 비공식 자료에만 언급 (수익화 기능에만 필요하다는 내용) | 콘솔 확인 |
| 검수 기간 | 공식 안내 영업일 2~3일, 출시 사례에서는 4일 | 실제 제출 |
