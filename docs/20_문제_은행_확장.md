# 20. 문제 은행 확장 (하루 20문제 × 1년)

목표: 하루 목표를 20문제로 정한 사용자도 365일 동안 매일 새 문제를 만난다. 맞춤 설정이 무엇이든 마찬가지다.

## 1. 필요한 문항 수

- 한 사용자가 1년에 푸는 문제: 20 × 365 = **7,300**문항 (보너스 5+5문제는 빼고 센다. 보너스까지 매일 풀면 약 243일).
- 맞춤 설정마다 문제를 내는 분류가 다르다(`src/lib/study.ts` `profileCategories`). 취미·여행은 일상 영어 하나뿐이라 **일상 영어만으로 7,300문항**이 필요하다. 나머지 설정은 두 분류를 번갈아 쓰므로 분류마다 그 절반 이상이면 된다.
- 출제 규칙(2026-10-25 바꿈): 원하는 난이도의 새 문제가 떨어지면 가까운 난이도의 새 문제를 먼저 내고, 새 문제가 모두 떨어졌을 때만 복습한다(`pickDaily`). 그래서 난이도별이 아니라 **분류 합계**로 보장된다. 예전 규칙(같은 난이도 복습 먼저)이었다면 정답률·시작 실력마다 필요한 난이도가 달라 32,052문항이 필요했다.

| 분류 | 기초 | 중급 | 심화 | 합계 |
|------|------|------|------|------|
| 일상 | 1,100 | 2,200 | 4,000 | 7,300 |
| 개발 · 직장 · 학교 · 토익 (각각) | 550 | 1,100 | 2,000 | 3,650 |
| **전체** | | | | **21,900** |

- 난이도 비율 15:30:55는 하루 20문제 사용자의 실제 수요를 따랐다. 하루 20문제면 열흘 안에 레벨 8 이상이 되고, 그 뒤로는 심화 80%·중급 20%로 출제된다. 정답률이 낮아 레벨이 천천히 오르는 사용자는 중급을 더 많이 쓴다. 비율이 어긋나도 새 문제 우선 규칙 덕분에 새 문제는 끊기지 않고, 가끔 난이도가 한 단계 다른 문제가 나올 뿐이다.
- 진행 확인: `npm run questions:report` (분류·난이도별 현재/목표, 맞춤 설정마다 버티는 날수, 품질 신호)

## 2. 파일과 모드

- 기존 1,425문항: `src/data/questions.json`. 기기 모드 번들과 서버에서 쓴다.
- 추가 문항: `src/data/questions.extra.json` (id 1426부터). **서버 모드에서만** 쓴다. 기기 모드 번들에 넣으면 6.7MB(gzip 1.8MB)가 되어 첫 로딩이 크게 느려지기 때문이다. 두 파일 모두 저장소에 올리지 않는다.
- 1년 보장은 서버 모드에서만 성립한다. 기기 모드는 지금처럼 1,425문항이다.
- `npm run check:bundle`은 추가 문항이 어느 모드의 클라이언트 번들에도 들어가지 않았는지 확인한다. 문장이나 해설이 번들에 있으면 유출로 본다. 단, 기기 모드 번들에는 기본 문항이 들어 있으므로 기본 문항과 글자까지 같은 해설은 근거로 쓰지 않는다(2026-10-25, 이 때문에 추가 문항 5개를 유출로 잘못 판정했었다).

## 3. 생성 기준

README의 "문제 작성 기준" 1~6을 모두 지킨다. 문항 수가 늘어 4번은 이렇게 바꾼다.

- **같은 문장은 금지, 같은 표현을 다른 문장으로 다시 묻는 것은 허용**(복습). 다만 같은 분류에서 같은 정답 단어가 몰리지 않게 주제와 표현을 넓게 퍼뜨린다.

### 난이도

| 난이도 | 묻는 것 | 문장 길이 |
|--------|---------|-----------|
| 기초 | 자주 쓰는 단어, 기본 문법(시제, 전치사, 관사, 단·복수, 조동사, 비교급), 기본 구동사 | 6~10단어 |
| 중급 | 연어(collocation), 구동사, 동명사·to부정사, 관계사, 기본 가정법, 업무·학업 고정 표현 | 8~14단어 |
| 심화 | 관용구, 뉘앙스를 구별해야 하는 어휘, 도치·가정법·분사구문, 분야 전문 표현 | 10~18단어 |

- 대상 수준: 가장 쉬운 기초도 기본 문법을 배운 중학생 정도가 기준이다. 알파벳·파닉스·그림 단어부터 배우는 초등 입문자용 문항은 만들지 않는다(만들려면 별도 분류와 화면이 필요하다).
- 한 묶음 안에서 같은 문법 포인트가 몰리지 않게 한다. 1차 학교 심화는 도치가 4문항이라 2문항으로 줄였다.

### 분류별 주제

- **개발**: 코드 리뷰, 배포·롤백, 장애 대응·모니터링, 테스트, 설계·아키텍처, 보안, 데이터베이스, 프론트엔드·모바일, API, 스프린트·회의, 문서화, 성능
- **직장**: 이메일, 회의, 일정 조율, 보고·성과, 협상·영업, 채용·인사, 출장, 고객 응대, 프로젝트 관리, 사내 소통
- **일상**: 쇼핑, 식당·카페, 교통·길 찾기, 여행·숙소, 건강·병원, 날씨, 집안일, 취미·운동, 친구·가족·약속, 감정, 전화·메시지, 공공장소, 관용 표현
- **학교**: 수업·과제·시험, 캠퍼스 생활, 발표·토론, 연구·논문 표현, 학업 계획·유학
- **토익**: Part 5 유형(품사, 시제, 수 일치, 대명사, 전치사·접속사, 관계사, 분사, 수동태, 어휘)을 비즈니스 공지·이메일·광고 문맥으로

### 정답이 하나뿐이게

- 오답 보기는 (1) 그 자리에 문법적으로 들어갈 수 없거나 (2) 문맥상 뜻이 분명히 틀려야 한다. 그 자리에 들어가도 말이 되는 유의어를 오답으로 두지 않는다.
- 보기 네 개는 같은 종류로 맞춘다(같은 품사의 다른 단어, 또는 같은 단어의 다른 형태).
- 해설은 해요체 1~2문장으로 왜 정답인지(문법 근거나 뜻) 쓰고, 헷갈리기 쉬운 오답이 있으면 차이를 짚는다.
- 해설에 정답 단어를 쓴다. "don't 뒤에는 동사원형이 와요"가 아니라 "don't 뒤에는 동사원형 close가 와요".
- 기존 문항의 해설을 그대로 가져오지 않는다. 문항의 맥락을 한마디 넣어 문항마다 다르게 쓴다.

1~5차 검토에서 실제로 고친 오답 보기 유형. 묶음마다 이 목록으로 다시 본다.

| 유형 | 고치기 전 예 | 문제 |
|------|--------------|------|
| 넣어도 뜻이 통하는 명사 | a useful **frame** (정답 framework), **Tutor** fees (Tuition), a false **promise** (premise), a **quarterly** survey (quantitative) | 정답이 둘 |
| 넣어도 뜻이 통하는 동사 | **substitute** your claims (substantiate), **reflected** the findings (refuted), **overlook** all decisions (oversee) | 정답이 둘이거나 옛 뜻으로 맞음 |
| 물리적으로 말이 되는 전치사 | put your phone **on** your bag (in), shuttle service **at** the airport (to) | 정답이 둘 |
| 영국식 영어에서 맞는 형태 | recommended that each student **chooses** (choose) | 지역에 따라 정답 |
| 관용구의 한 단어를 바꿔도 통하는 표현 (2차) | kept her **calm** (cool), foot the **cost** (bill), pick your **mind** (brain), It's no use **to complain** (complaining) | 덜 쓰일 뿐 맞는 말 |
| 글자 그대로 읽으면 말이 되는 보기 (2차) | made a **path** for the truck (beeline), sweep it under the **bed** (rug), made no **jokes** about it (bones) | 관용구가 아니어도 뜻이 통함 |
| 시간 단서가 없어 과거형도 맞는 습관 문장 (3차) | My grandfather **reads** the newspaper every morning (read도 됨), The bus **comes** at 7:30 every morning (came도 됨) | 정답이 둘. right now·yesterday 같은 단서를 넣는다 |
| 기존 문항과 같은 문장 | The meeting room is ___ the end of the hall. | 검사기가 잡음, 새 문장으로 교체 |
| 기존 문항과 단어만 조금 다른 문장 (3차) | not good at cooking, but I'm **learning** (기존 문항은 trying), allergic to peanuts, raise your hand | 검사기가 못 잡음. 단어 겹침으로 찾아 상황을 바꾼다 |
| 해석 속 금지 표현이 다른 단어 안에 들어 있음 (3차) | 기**술을**, 미**술을** | 한국어는 부분 문자열로 찾아서 걸린다. 기술로, 그림에 처럼 바꾼다 |
| 일상 표현에 들어 있는 금지 단어 (4차) | flu **shot** | 검사기가 잡음. flu vaccine처럼 같은 뜻의 다른 말로 바꾼다 |
| 이미 나온 표현을 다른 형태로 다시 묻는 문장 (4차) | **stipulates** (기존 정답 stipulate), splash out on (기존 문항은 빈칸이 out), look down on (기존 문항은 빈칸이 down), **potluck** dinner | 같은 표현의 반복. 정답 후보를 굴절형과 구동사·관용구의 단어 하나하나까지 기존 정답과 대조한다 |
| 관용구의 한 단어만 빈칸이던 기존 문항 (5차) | duct tape (기존 문항은 duct ___, 정답 tape), rabbit hole, drawing board, in lieu of (기존은 in ___ of), pull their weight | 정답 단어끼리 대조하면 못 잡는다. 빈칸을 채운 문장 전체에서 그 표현이 나왔는지 찾는다 |
| 대조 스크립트가 놓친 굴절형 (5차) | **excelled** (excel의 끝 자음을 겹친 형태), **strode** (stride의 불규칙 과거) | 같은 단어의 반복. 합치기 전에 정답을 기존 정답과 글자 그대로도 대조한다 |
| 보기나 해석에 숨은 금지 표현 (5차) | 보기 shoot up, smoke alarm, 해석의 입**술을**·기**술을**·풀이 **죽었**어요 | 검사기가 잡음. 다른 보기나 말로 바꾼다 |

### 묶음 작업 순서

1. 분류·난이도별로 100문항 안팎의 묶음을 쓴다. 정답 위치는 1~4번이 고르게. 4차부터는 쓰기 전에 정답 후보가 은행에 이미 있는지(굴절형, 구동사·관용구의 각 단어 포함) 보조 스크립트로 먼저 확인하고, 정답을 첫 보기에 쓴 뒤 스크립트로 섞는다(4문항마다 1~4번이 한 번씩). 5차부터는 합치기 전에 두 가지를 더 본다. 빈칸을 채운 문장에서 정답과 앞뒤 단어로 이룬 표현이 기존 문항에 나왔는지, 정답이 기존 정답과 글자까지 같은지.
2. 묶음 검사 `npm run questions:batch -- <묶음.json>`: id·형식·금지 표현·기존 문항과 같은 문장(오류), 같은 해설·문장 길이·해석 어미·사람 지칭(경고). 묶음 파일은 저장소 밖에 둔다.
3. 위 오답 보기 유형표로 전 문항을 읽고 고친다. 3차부터는 기존 문항과 내용어가 많이 겹치거나 정답이 같은 문장을 보조 스크립트로 뽑아 함께 본다(저장소 밖, 묶음 파일과 같은 곳).
4. `npm run questions:batch -- <묶음.json> --merge`로 추가 문제 은행에 합친다(오류가 있으면 합치지 않는다). 그다음 `npm test`, `npm run questions:report`, 두 모드 `npm run check:bundle`.
