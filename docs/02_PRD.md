# 02. PRD (Product Requirements Document)

## 1. 문제 정의

개발자는 영어 문서와 커뮤니케이션을 매일 접하지만 따로 시간을 내 공부하기 어렵다. 기존 영어 앱은 일상 회화 중심이고, 한 번에 요구하는 학습량이 크다.

## 2. 제품 한 줄 정의

토스 앱 안에서 하루 5문제, 1~2분 만에 끝나는 개발자·일상 영어 퀴즈.

## 3. 사용자 페르소나

| 페르소나 | 상황 | 원하는 것 |
|----------|------|-----------|
| 주니어 개발자 A | PR 리뷰 코멘트를 영어로 써야 함 | 자주 쓰는 표현을 짧게 익히기 |
| 취업 준비생 B | 해외 지원용 영문 이력서 준비 중 | 매일 조금씩 영어 감 유지 |
| 일반 사용자 C | 토스 앱을 자주 엶 | 잠깐 머리 쓰는 가벼운 학습 |

## 5. 하지 않는 것

- 다른 사용자와 점수 비교, 랭킹, 순위 공유
- 보상이 현금성 가치를 갖는 포인트
- 문제 다시 풀기로 XP를 반복 획득하는 구조

## 6. 성공 지표

| 지표 | 정의 | MVP 목표 (출시 후 4주) |
|------|------|------------------------|
| D1 재방문율 | 첫 완료 다음 날 다시 완료한 비율 | 30% |
| D7 재방문율 | 첫 완료 7일 뒤 완료한 비율 | 15% |
| 완료율 | 시작한 사용자 중 5문제 끝낸 비율 | 80% |
| 평균 streak | 활성 사용자의 연속 학습일 평균 | 3일 |

목표 수치는 기준선이 없는 상태에서 정한 초기값이다. 수집은 SDK의 `Analytics`·`eventLog` 사용을 검토한다.

## 7. 사용자 경험 원칙

1. 열자마자 바로 문제를 푼다. 온보딩 화면을 두지 않는다.
2. 틀려도 손해가 없다. 정답 수와 무관하게 완료 보너스를 준다.
3. 한 화면에 한 문제만 보여 준다.

## 8. 제약

- 앱인토스 WebView 환경에서 동작해야 한다.
- 서버 없이 정적 번들로 배포한다 (MVP). 서버 렌더링은 출시 가이드상 쓸 수 없다.
- 라이트 모드만 지원한다 (출시 가이드).
- 앱 이름은 10자 이내, appName은 출시 후 수정할 수 없다.
