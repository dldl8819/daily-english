## 2. 비기능 요구사항

| ID | 분류 | 요구사항 | 상태 |
|----|------|----------|------|
| NFR-01 | 성능 | 첫 화면은 일반 모바일 회선에서 2초 안에 표시되어야 한다. | 측정 전 |
| NFR-02 | 호환성 | 앱인토스 WebView(iOS, Android)에서 동작해야 한다. | `.ait` 빌드 완료, 실기기 미확인 |
| NFR-03 | 반응형 | 360px 이상 폭에서 가로 스크롤 없이 표시되어야 한다. | [구현] |
| NFR-04 | 테마 | 기본은 라이트 모드이고 기기 다크 모드를 따르지 않는다 (앱인토스 출시 가이드). 고대비 모드 글자 대비는 7:1 이상. | [구현] |
| NFR-05 | 가용성 | 서버 없이 정적 파일만으로 동작해야 한다 (MVP). 서버 렌더링 금지. | [구현] |
| NFR-06 | 견고성 | 저장소 접근이 막혀도 화면이 깨지지 않아야 한다. | [구현] |
| NFR-07 | 개인정보 | MVP는 개인정보를 수집하지 않는다. | [구현] |
| NFR-08 | 품질 | 핵심 로직과 문제 데이터 형식은 단위 테스트로 검증해야 한다. | 앱 6,150개·서버 31개 통과 (2026-10-26, 추가 문제 은행이 있는 로컬 기준) |
| NFR-09 | 콘텐츠 | 모든 문제는 정답이 하나로 확정되어야 하고 사람이 검수해야 한다. | 형식 검사 통과, 사람 검수 대기 |
| NFR-11 | 영속성 | 앱을 종료했다 다시 열어도 진행 상황이 유지되어야 한다 (출시 가이드). | SDK Storage 사용, 실기기 미확인 |
| NFR-12 | 조작 | 핀치 줌을 막아야 한다 (출시 가이드). | [구현] |
| NFR-10 | 접근성 | WCAG 2.1 AA를 따르고, 스크린리더 사용자가 처음부터 결과까지 혼자 풀 수 있어야 한다 ([17_접근성](17_접근성.md)). | [구현], 실기기 확인 대기 |
| NFR-13 | 보안 | 의존성 취약점은 발견 즉시 조치한다 (`npm audit` 0건 유지). | 0건 |

## 3. 제약 사항

- 앱인토스 정책: 사행성 요소 금지, 앱 이름 10자 이내, appName 수정 불가, 비게임 출시 가이드 ([16_앱인토스_연동_조사](16_앱인토스_연동_조사.md))
- 개발 환경: Next.js 정적 export, TypeScript
