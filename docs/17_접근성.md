# 17. 접근성

- 기준: WCAG 2.1 AA, 스크린리더(VoiceOver, TalkBack) 사용자를 1차 대상으로 둔다.
- 점검일: 2026-10-21

## 2. 화면 모드

저시력 사용자는 불편한 조건이 서로 다르다. 눈부심·광과민이 있으면 어두운 화면이, 난시가 있으면 밝은 배경의 고대비가 더 읽기 쉬울 수 있다. 그래서 사용자가 고를 수 있게 했다.

| 모드 | 대상 | 화면 | 글자 대비 | 켜지는 조건 |
|------|------|------|-----------|-------------|
| 기본 | 일반 | 밝은 회색 배경, 흰 카드 | 4.5:1 이상 (AA) | 처음 열 때 |
| 고대비 | 난시, 저시력 | 흰 배경, 검정 글자, 2~3px 검정 테두리, 진행 바 흰 바탕+검정 테두리 | 7:1 이상 (AAA) | 사용자 선택, 또는 기기 "대비 높이기"(`prefers-contrast: more`)가 켜져 있고 고른 적이 없을 때 |
| 어둡게 | 눈부심, 광과민 | 짙은 회색 배경(`#1a1c20`), 연한 회색 글자(`#e6e8eb`). 순검정·순백을 피해 번짐을 줄임 | 4.5:1 이상 (AA) | 사용자가 앱 안에서 고를 때만 |

- 화면 위쪽 "화면" 라디오 묶음(`fieldset`/`legend`)에서 고른다. 각 선택지는 설명("눈부심을 줄인 어두운 화면" 등)을 `aria-describedby`로 읽어 준다. 선택된 항목에는 색 외에 "✓"도 붙는다.
- 고른 값은 SDK Storage와 localStorage에 저장(`daily-english:theme:v1`)해 다음에도 유지한다.
- 첫 화면이 밝게 번쩍이지 않도록, React보다 먼저 실행되는 작은 스크립트가 localStorage 값을 읽어 적용한다. 광과민 사용자에게 밝은 화면이 잠깐 보이는 것도 자극이 되기 때문이다.
- 앱인토스 내비게이션 바도 `NavigationBar.setOptions({ theme, backgroundColor })`로 맞춘다.

## 3. 앱인토스 가이드와 충돌하는 항목

| 항목 | 가이드 | WCAG | 대응 |
|------|--------|------|------|
| 핀치 줌 | 막아야 함 | 1.4.4 텍스트 200% 확대 가능해야 함 | 가이드를 따르되, 글자·간격을 모두 `rem`으로 써서 기기 글꼴 크기 설정을 따르게 함. 토스 앱 WebView에서 시스템 글꼴 크기가 실제로 반영되는지는 실기기 확인 필요 |
| 다크 모드 | "미니앱 테마는 라이트 모드로 구현돼 있어요." 다크 모드 금지인지, 기본이 라이트여야 한다는 뜻인지 불명확 | 해당 기준 없음 (접근성상 필요한 사용자 있음) | 기본은 라이트, 기기 다크 모드를 따르지 않음. "어둡게"는 사용자가 직접 고를 때만. 심사에서 문제가 되면 `THEMES`에서 dark만 빼면 됨. 심사 전에 개발자 커뮤니티에 허용 여부 문의 권장 |

## 4. 자동 검증

| 테스트 | 내용 |
|--------|------|
| `src/app/contrast.test.ts` | CSS 토큰을 모드별로 읽어 대비 계산. 글자 12쌍(기본·어둡게 4.5:1, 고대비 7:1), 그래픽·포커스 3쌍(3:1). 어둡게 모드의 순검정·순백 사용 금지 |
| `src/lib/theme.test.ts` | 모드 값 검증, 첫 모드 결정(대비 설정만 따름), 첫 화면 전 스크립트 동작 |
| `src/components/DailyChallenge.test.tsx` | jsdom 렌더링 + axe-core 검사(색 대비 제외), 제목 구조, `lang`, 빈칸 읽기, 결과 글자 표시, 포커스 이동, 키보드 조작, 화면 모드 전환·저장·복원, 기기 다크 모드 무시 |

자동 검사로 실제 문제를 하나 잡았다. 고대비 모드에서 진행 바 바탕(검정)과 채움(진한 파랑)의 대비가 2:1이라, 바탕을 흰색 + 검정 테두리로 바꿨다.

## 5. 남은 확인 (실기기)

| ID | 확인 | 방법 |
|----|------|------|
| A-1 | VoiceOver(iOS)로 처음부터 결과까지 풀기 | 토스 앱 QR 테스트 |
| A-2 | TalkBack(Android)으로 같은 흐름 | 토스 앱 QR 테스트 |
| A-3 | 영어 문장이 영어 음성으로 읽히는지 | A-1, A-2 중 확인 |
| A-4 | 시스템 글꼴 크기 최대에서 글자가 커지고 화면이 깨지지 않는지 | 기기 설정 |
| A-5 | 앱인토스 내비게이션 바(뒤로가기)가 스크린리더로 읽히는지 | A-1, A-2 중 확인 |
| A-6 | "어둡게"를 고르고 앱을 다시 열 때 밝은 화면이 번쩍이지 않는지, 내비게이션 바도 어두워지는지 | 토스 앱 QR 테스트 |
| A-7 | iOS "대비 증가", Android "고대비 텍스트" 설정에서 고대비 모드로 시작하는지 | 기기 설정 |

자동 검사는 구조와 속성을 보장할 뿐, 실제 스크린리더에서 자연스럽게 들리는지는 보장하지 않는다. 가능하면 시각장애인 사용자에게 직접 사용성 테스트를 받는다.
